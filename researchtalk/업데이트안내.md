# 이번 수정: Enter 전송과 빨간 점

1. `app` 폴더의 파일을 기존 Vercel 프로젝트에 덮어쓰고 배포하세요. index.html 생성과 서비스 워커 캐시 갱신은 완료했습니다.
2. 앱과 같은 사이트의 브라우저 탭을 모두 닫았다 다시 여세요.
3. 노란색 ‘읽지 않은 대화 표시 설정이 필요해요’ 안내가 나오면, 현재 앱의 Supabase 프로젝트 SQL Editor에서 `supabase/03-unread.sql` 전체를 실행하고 ‘다시 연결’을 누르세요. 기존 대화는 유지되며 이 파일은 재실행해도 됩니다. 이전 초기 설정 파일로 덮어썼을 때도 이 파일을 실행하면 읽음 조회가 복구됩니다.

## 입력 방법
- Enter: 메시지 전송
- Shift+Enter: 줄바꿈
- 한글 입력 조합 중 Enter: 글자 확정만 수행
- 공백만 입력했거나 전송 중일 때는 중복 전송하지 않습니다.

## 빨간 점 확인 방법
서로 다른 두 계정으로 로그인하세요. 받는 사람은 ‘오늘’ 탭에 머물고, 보내는 사람이 단체방 또는 수락된 개인방에 메시지를 보내세요. 받는 사람의 대화 탭과 해당 대화방에 빨간 점이 나타납니다. 실시간 연결이 지연되면 주기 갱신(약 8초)으로 반영됩니다.

내가 보낸 글에는 내 화면의 빨간 점이 생기지 않습니다. 같은 계정으로 두 기기를 테스트하지 마세요. 해당 대화방이 화면에 열려 있고 메시지가 보이면 읽음 처리되어 점이 사라지는 것이 정상입니다. 앱을 닫은 동안의 푸시 알림은 포함하지 않습니다.

서버가 미독 정보를 제공하지 않는 경우를 더 이상 미독 없음으로 숨기지 않고, 설정 안내를 보여줍니다. 다른 창에 가려져 포커스가 없는 앱에서는 읽음 처리하지 않습니다.

실제 배포·계정 로그인 확인은 수행하지 않았습니다. 이전 연구 배경과 달력 초록 점 기능도 모두 포함됩니다.

# 이번 화면·달력 수정

논문 원고를 닮은 한국어 예시 배경, 종이색 카드와 녹색 메뉴를 적용했습니다. 달력에서 내가 작성한 공유 약속과 개인 할 일은 초록색 점으로, 다른 참여자가 작성한 공유 약속은 분홍색 점으로 표시됩니다. 둘 다 있으면 두 점이 나타납니다. 개인 할 일은 본인에게만 보입니다. 완료한 할 일도 그날의 기록으로 점이 유지됩니다.

**이번 디자인과 달력 표시는 Supabase 수정 없이 app 폴더 파일만 기존 Vercel 프로젝트에 업데이트하면 됩니다.** 실행 파일 생성과 캐시 버전 변경은 완료했습니다.

이 압축에는 앞서 추가한 미독 기능도 포함됩니다. 이전에 03-unread.sql을 실행했다면 다시 실행할 필요가 없습니다. 아직 미독 설정을 하지 않았다면 아래 이전 안내의 1번을 한 번 진행하세요.

브라우저가 로컬 미리보기 주소를 차단해 실제 렌더링 확인은 완료하지 못했습니다. 모의 화면에서 본인 일정·다른 참여자 약속·같은 날짜의 두 점 표시를 검증했습니다.

# 기존 주소를 유지하며 업데이트하기

이번 수정: 대화 탭과 대화방에 빨간 점이 나타납니다. 방을 열면 가장 먼저 안 읽은 메시지의 날짜와 위치로 이동하며 ‘여기부터 읽지 않은 대화’를 표시합니다. 화면에 보인 메시지만 읽음 처리하고, 읽음 기록은 계정별로 서버에 저장합니다.

## 1. 이번에만 Supabase 추가 설정
6명 계정이 있는 Supabase 프로젝트의 SQL Editor에서 `supabase/03-unread.sql` 전체를 붙여넣고 Run을 누르세요. 기존 대화와 계정은 유지됩니다. 다시 실행해도 됩니다. 기존 초기 설정 SQL은 다시 실행하지 마세요.

이전 버전에는 읽음 기록이 없었으므로 처음 적용하면 기존 상대방 메시지도 읽지 않은 것으로 표시됩니다. 대화를 확인하면 표시가 사라집니다.

## 2. Vercel 기존 프로젝트 업데이트
프로젝트를 삭제하지 마세요. 현재 프로젝트의 Settings → Git에서 저장소 연결 여부를 확인하세요.

### GitHub가 연결된 경우
연결된 저장소에서 기존 앱 파일이 있는 위치에 이 압축의 `app` 안 파일을 덮어쓰고 Commit changes를 누르세요. 배포용 브랜치(보통 main)에 반영되면 Vercel이 자동 배포합니다. 기존 루트 폴더 구조를 유지하세요. index.html은 이미 새 코드로 생성되어 있습니다.

### GitHub 연결 없이 폴더로 올린 경우
컴퓨터에 Node.js를 설치한 뒤, 새 압축의 `app` 폴더에서 터미널을 열고 실행하세요.

```sh
npx vercel login
npx vercel link
npx vercel --prod
```

link 과정에서 현재 프로젝트를 소유한 계정/팀을 선택하고 `Link to existing project?`에는 Y를 선택하세요. **Vercel 관리 화면에 표시된 기존 프로젝트 이름**을 고르세요. 주소와 프로젝트 이름이 항상 같지는 않습니다. 새 프로젝트 만들기를 선택하지 마세요. 이후에는 같은 폴더에서 파일 수정 후 `npx vercel --prod`만 실행하면 됩니다. `.vercel` 연결 폴더를 보관하세요.

소스 파일(app.js, styles.css 등)을 직접 수정하면 배포 전에 `npm run build`를 실행하세요. sw.js의 CACHE_VERSION도 새 값으로 바꾸세요. 이번 전달본은 이미 빌드·캐시 버전 변경을 완료했습니다.

Vercel 화면의 Redeploy는 기존 소스를 다시 배포하는 기능이며 컴퓨터에서 바꾼 파일을 자동으로 가져오지 않습니다.

## 3. 휴대폰 확인
배포 완료 후 앱과 해당 사이트의 브라우저 탭을 모두 닫았다 다시 여세요. 한 사람은 홈 화면에 머무르고, 다른 사람이 메시지를 보내 빨간 점을 확인하세요. 대화 탭이나 개인방을 누르면 첫 미독 위치가 보입니다. 이전 날짜부터 확인 중이라면 날짜 선택으로 다른 날을 보거나 방을 다시 눌러 다음 미독 위치로 이동할 수 있습니다.

이 표시는 앱 안의 빨간 점입니다. 앱이 닫혀 있을 때 휴대폰에 뜨는 푸시 알림이나 홈 화면 아이콘 배지는 포함하지 않습니다. 앱으로 돌아오면 최신 내용을 불러옵니다.

검증: 로컬 PostgreSQL 호환 테스트 DB와 여섯 개의 모의 화면으로 확인했습니다. 실제 배포와 아이폰·안드로이드 실기기 확인은 아직 하지 않았습니다.
