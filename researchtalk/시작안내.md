# researchtalk 시작하기

달력, 오늘의 요일, 개인별 할 일, 함께 보는 약속, 최대 6명의 단체 대화와 초대형 개인 대화를 담았습니다. 아이폰·안드로이드에서 홈 화면에 추가하는 PWA입니다.

새 Supabase 프로젝트 pmeekvclikkxocudmerb의 주소와 공개 키를 넣었습니다. **아직 이 버전의 SQL을 실제 Supabase에 실행하거나 Vercel에 배포하지는 않았습니다.** 아래 두 가지를 한 번 진행하면 됩니다.

## 1. researchtalk 저장 공간 만들기

1. [researchtalk Supabase 프로젝트](https://supabase.com/dashboard/project/pmeekvclikkxocudmerb)를 엽니다.
2. **SQL Editor → 새 쿼리**를 선택합니다.
3. 이 압축의 **supabase/researchtalk-setup.sql**을 메모장 등으로 열어 내용 전체를 복사합니다.
4. 새 쿼리에 붙여넣고 **Run**을 누릅니다.
5. 결과에 MR.Cho, Mr.K, Madam.Um, Madam.Hee, Madam.Fall, Madam.MK 여섯 계정이 나오면 준비됐습니다. 이미 앱에서 이름을 바꿨다면 바뀐 이름이 나옵니다.

참여자는 보내주신 여섯 계정입니다. 이메일과 비밀번호도 그대로 씁니다. 새 이름은 앱의 **참여자 → 내 이름 바꾸기**에서 정할 수 있습니다. 기존 두 사람 앱의 대화를 이 단체방으로 옮기지 않습니다. researchtalk는 `rt_`로 시작하는 별도 테이블에 저장하며 기존 `couple_` 테이블은 보존합니다.

SQL은 `01-researchtalk.sql`과 `02-start-members.sql`을 합친 것입니다. 합친 파일을 실행했다면 나머지 두 파일을 따로 실행할 필요는 없습니다. 다시 실행해도 기존 기록을 지우지 않습니다.

## 2. Vercel에 올리기

1. **app 폴더 안의 파일 전체**를 GitHub 저장소에 올립니다. `index.html`, `vercel.json`, `icons` 폴더 등이 첫 화면에 보이게 합니다.
2. Vercel 프로젝트에서 해당 저장소를 연결합니다. 기존 커플 앱도 계속 쓰려면 researchtalk용 새 프로젝트를 만듭니다.
3. 프레임워크는 **Other**, 설치·빌드 명령은 비우고 출력 폴더는 **.**으로 둡니다. 설정은 `vercel.json`에도 들어 있습니다.
4. 저장소에 `app` 폴더째 넣었다면 **Root Directory**를 `app`으로 정합니다.
5. 생성된 **HTTPS 주소**를 각 휴대폰에서 열고, 앞서 만든 각자 이메일·비밀번호로 로그인합니다.

받은 `index.html`에는 화면과 동작 코드가 이미 들어 있습니다. 별도 CSS 파일이 연결되지 않아 화면이 깨지던 문제를 피하도록 구성했습니다. 정적 앱에는 별도의 서버 코드가 필요하지 않습니다.

## 3. 여섯 명이 바로 로그인하기

여섯 명 등록 SQL을 이미 성공적으로 실행했다면 단체방 초대 없이 각자 이메일·비밀번호로 로그인하면 됩니다. 이 앱은 https://researchtalk-mu.vercel.app/ 에 다시 배포합니다.

### 정원이 남아 있을 때의 초대 방법

현재처럼 관리자가 계정을 직접 만드는 방법이 가장 적은 설정으로 시작할 수 있습니다.

1. Supabase **Authentication → Users → Add user → Create new user**에서 새 참여자의 이메일과 앱 비밀번호로 계정을 만듭니다. **Auto Confirm User**를 체크합니다. 비밀번호는 해당 참여자에게만 전달합니다.
2. researchtalk 앱의 **참여자 → 초대 링크 만들기 → 링크 복사**를 누릅니다.
3. 그 링크를 **한 사람에게만** 직접 보냅니다. 앱이 이메일이나 메시지를 자동으로 보내지는 않습니다.
4. 초대받은 사람은 링크를 열어 **로그인** 탭에서 만들어 둔 계정으로 로그인합니다.
5. 이름과 초대 코드가 나타나면 이름을 적고 **참여하기**를 누릅니다. 링크로 들어오면 코드는 자동으로 채워집니다.
6. 나머지 참여자도 같은 방법으로 초대합니다. 초대 링크는 한 번만 쓸 수 있고 7일 뒤 만료됩니다. 참여자와 유효한 미사용 초대를 합해 여섯 자리까지만 발급됩니다.

쓰지 않을 초대는 만든 사람이 **초대 취소**로 없앨 수 있습니다. 이미 계정을 만들었어도 초대에 참여하기 전에는 대화와 일정을 읽을 수 없습니다. 개인 대화 초대와 단체방 참여 초대는 별개입니다.

### 참여자가 직접 가입하게 하려면

앱의 **초대받아 가입**도 구현했습니다. 이 방식은 Supabase의 이메일 인증 설정이 필요합니다.

- Authentication의 **URL Configuration**에서 **Site URL**과 **Redirect URLs**에 실제 researchtalk 배포 주소를 등록합니다.
- **Allow new users to sign up**을 켜고, 이메일 인증을 사용하는 경우 **Custom SMTP**를 연결합니다.
- 초대받은 사람이 이름·이메일·새 비밀번호·초대 코드를 입력합니다. 인증 메일의 링크를 누른 뒤 로그인하면 참여할 수 있습니다.
- 기본 Supabase 메일 발송은 프로젝트 팀 계정으로 수신 대상이 제한됩니다. 일반 참여자에게 메일이 오지 않으면 앞의 관리자 계정 생성 방식으로 시작할 수 있습니다. 인증 설정을 끄도록 바꾸지는 않았습니다.

공식 안내: [이메일 가입](https://supabase.com/docs/reference/javascript/auth-signup), [메일 발송 설정](https://supabase.com/docs/guides/auth/auth-smtp), [인증 후 돌아올 주소](https://supabase.com/docs/guides/auth/redirect-urls).

## 4. 개인 대화 시작하기

1. **대화 → + 개인 대화** 또는 **참여자**에서 상대 한 명을 고릅니다.
2. **개인 대화 초대**를 누르면 상대의 참여자 화면에 초대가 나타납니다.
3. 상대가 **수락**하면 두 사람의 대화 목록에 개인방이 생깁니다. **거절**할 수도 있습니다.
4. 수락한 두 사람만 메시지, 날짜별 기록, 보관과 요약을 볼 수 있습니다. 다른 네 사람은 서버에서도 그 방에 접근할 수 없습니다.

Supabase 프로젝트 관리자는 데이터베이스 자체를 관리할 수 있습니다. 개인 대화 기능은 앱 참여자 사이의 접근 제한이며, 종단간 암호화 메신저는 아닙니다.

## 매일 사용하는 방법

- **오늘**: 오늘의 날짜와 요일, 달력이 보입니다. 날짜를 누르면 그날의 내 할 일을 관리합니다.
- **오늘의 할 일**: 본인만 읽고 체크·삭제할 수 있습니다. 날짜를 바꿔 다른 날의 할 일도 적을 수 있습니다.
- **이번 달의 약속**: 여섯 명이 함께 봅니다. 날짜·시간·이름·메모를 적고, 본인이 만든 약속만 수정·삭제합니다. 달력의 점이 약속을 표시합니다.
- **대화**: 여섯 명이 같은 단체방에서 동시에 보낼 수 있습니다. 다른 사람의 새 메시지나 삭제를 자동으로 반영합니다. 본인 메시지만 삭제할 수 있습니다.
- **날짜별 보기·하루 보관·파일 저장**: 방마다 구분해서 지난 대화를 보고 하루 기록을 글 파일로 내려받습니다. 보내는 순간 자동 저장되므로 보관 버튼을 누르지 않은 대화도 남습니다.
- **하루 대화 요약**: 기존과 같이 선택 기능을 준비했으며, 실제 AI는 아직 연결하지 않았습니다. 연결하려면 `optional-ai/AI-연결안내.md`를 참고합니다.

## 휴대폰 홈 화면에 추가

- 아이폰: 사파리로 배포 주소 열기 → 공유 → **홈 화면에 추가**. ‘웹 앱으로 열기’가 보이면 켭니다.
- 안드로이드: 크롬으로 배포 주소 열기 → 메뉴 → **홈 화면에 추가** 또는 **앱 설치**.

설치 이름은 **researchtalk**입니다. 주소창 없이 실행되고, 노치·홈 바 여백을 둡니다. 아이폰 180px 아이콘과 안드로이드 192px·512px·마스크용 아이콘을 포함합니다.

## 연결이 끊겼을 때

최근에 열었던 최대 12개 방·날짜의 기록을 기기에서 다시 읽을 수 있습니다. 연결이 끊긴 동안 새 전송을 완료했다고 표시하지 않으며, 입력한 글을 기기에 남깁니다. 인터넷이 돌아오면 최신 대화를 가져온 뒤 다시 보내세요. 자동 발송 대기열은 없습니다.

로그아웃하면 그 계정의 기기 캐시와 초안을 지웁니다. 서버의 대화·할 일·약속은 유지됩니다. 같은 기기를 다른 사람이 쓸 때도 이전 계정의 개인 대화를 앱에서 보여주지 않습니다.

## 확인한 내용과 남은 확인

실제 PostgreSQL 문법을 실행하는 로컬 환경과 여섯 개로 분리한 화면·통신 모의 환경에서 **22개 검사**를 통과했습니다. 동시 전송, 전송 응답 유실, 본인 삭제, 6명 제한, 개인방 초대·수락·접근 제한, 개인 할 일, 공유 약속, 재연결, 로그아웃 후 캐시 제거를 확인했습니다.

브라우저 확인용 연결이 차단되어 실제 화면 배치·터치·키보드 동작은 실물 브라우저에서 검증하지 못했습니다. 실제 Supabase 로그인·Realtime, 아이폰·안드로이드 설치, Vercel 배포와 실제 AI 호출은 아직 확인하지 않았습니다.

설정 후 여섯 계정으로 같은 단체방에 접속해 서로 한 문장씩 보내보세요. 두 사람끼리 개인방을 만든 다음 세 번째 계정에는 그 방이 보이지 않는지 확인합니다. 다른 휴대폰에서 약속은 보이고 개인 할 일은 보이지 않는지도 확인합니다.
